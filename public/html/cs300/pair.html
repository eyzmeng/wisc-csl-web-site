For our code you should follow CS300 course style guide ON TOP of these rules:

  1. Be consistent with everything: spacing, brace alignment, Javadoc punctuation, etc. We may not match each other's styles, but you must be consistent with YOURSELF.
  2. Wrap all comments at 76 characters (with the exception of submission header, hyperlinks, or possibly very long class names such as ArrayIndexOutOfBoundsException).
  3. Put at most two lines of code (dangerous code & return/break/continue) in any 'try' block unless you are using a try-finally construct OR whatever situation calls for it. (I will judge this accordingly.)
  4. Always prefer 'return condition;' to 'if (condition) return true;' and 'return !condition;' to 'if (condition) return false;' unless there is code after the if-statement or you plan to add more.
  5. Keep the first sentence (summary) of Javadoc 1-3 lines long. Get straight to the point, and if you have nuances to explain, put it in the remainder of the comment, e.g. Don't write: "This method is a method that uses the Baz Algorithm to foo the bar such that bar becomes shiny and..." Write: "This method foos the bar using the Baz Algorithm. The foo'd bar is shiny and..." Or better yet: "Foo(s) the bar using the Baz Algorithm." (Using either PEP-257-recommended imperative language or Oracle's guide of third-person language is completely fine as long as we are both consistent about it.)
  6. Any further complaints the Java compiler makes with -Xlint:all and the Javadoc generator makes with -Xdoclint:all MUST be fixed (except undocumented fields).

These should be very basic expectations. I expect to see you write code that goes beyond these recommendations. (I'm not like scary strict, but I *am* strict!) I only felt the need to lay them out due to my last collaboration being... unexpectedly "subpar".
